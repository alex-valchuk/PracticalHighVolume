# Backlog: gain product-level LLM integration experience

**Status:** not started
**Motivation:** interview question "Do you have commercial experience
integrating LLMs into a product?" Currently the answer is: "I have used
LLMs as a development tool, but not as a product component." Closing this
gap turns a hedged answer into a strong one.

## What "product-level LLM integration" means

Not using Copilot / Cursor / ChatGPT to write code. Instead:

- Calling an LLM API from application code.
- Handling prompts, retries, timeouts, rate limits, streaming.
- Grounding with retrieval (RAG) or tools.
- Observability of LLM calls (tokens, latency, cost).
- Graceful degradation when the LLM is unavailable.

## Candidate mini-projects (pick one, keep it small)

1. **Bookings summary endpoint.**
   `POST /api/bookings/{id}/summary` returns a human-readable paragraph
   describing the booking, generated by an LLM from the booking aggregate.
   Fallback to a templated string when the API key is missing or the call
   fails.

2. **Notification worker with LLM-generated text.**
   Notification Worker composes email / message bodies via LLM using
   booking + flight context. Template fallback on failure.

3. **RAG over the repo docs.**
   Small Q&A service that answers questions about ADRs, README, and specs
   using embeddings + vector store (pgvector is a natural fit, Postgres
   is already in the stack).

## Required architectural concerns (these are the interview talking points)

- Provider abstraction: do not couple the domain to a specific vendor.
- Configuration and secrets: API key via env var / Aspire parameter / K8s Secret.
- Timeouts + retries + circuit breaker around the LLM call (Polly).
- Cost and token accounting in metrics (OpenTelemetry counters).
- Determinism and safety: prompt injection from user data, output validation.
- Observability: trace the prompt/response pair as spans.
- Graceful degradation: hard fallback path that always works.

## Where it fits in the roadmap

Best as **Phase 11.x** (after service extraction and the YARP gateway from
Phase 10). It is orthogonal to the monolith-to-microservices line, so it
should not block Phase 9 or Phase 10.

## Definition of done

- One of the mini-projects above is implemented, tested, and deployed to
  both Docker Compose and Kubernetes.
- An ADR documents provider choice, fallback strategy, and cost/latency
  budget.
- An interview-ready answer exists: what was built, why, what broke, how
  it was fixed.
